Rebuilding the Northwind console

A three-year-old admin tool had grown to 140 screens and nobody could ship in it any more. We rebuilt the foundation without stopping feature work.

Console overview

Lead designer

The problem

Northwind's console had been extended by four different teams over three years. There were nine button styles, three date pickers and two competing grid systems. New features took roughly six weeks, and about a third of that was spent deciding what things should look like.

The obvious answer — a rewrite — was off the table. The console was generating most of the company's revenue and could not go dark for a quarter.

Approach

We audited every screen and catalogued the components in use. The audit produced a number that made the case for us: 47 distinct components doing the work of 18.

Adoption had to be easier than not adopting. That constraint decided almost every subsequent call.

Rather than freeze feature work, we shipped the new foundation underneath it. Each team migrated their own surface as they touched it, against a component library that was documented before it was published.

What we changed

  • Collapsed 47 components to 18, with real usage docs for each
  • One spacing scale and one type scale, both tokenised
  • A single data table that replaced five bespoke implementations
  • Keyboard and screen-reader passes built into the definition of done

Result

Nine months in, median feature build time dropped from six weeks to under three. The accessibility audit that had previously returned 180 issues came back with 11. Most usefully, three teams who had never contributed to shared code started opening pull requests against the library.
